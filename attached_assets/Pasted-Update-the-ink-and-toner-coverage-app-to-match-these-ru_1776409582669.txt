Update the ink and toner coverage app to match these rules exactly.

## Main correction

The app must **not** show color percentages that add up to more than 100% of the page.

Right now, the app is summing independent CMYK channel coverage values, which can exceed 100%. That is not the behavior I want.

I want the app to calculate **page-area coverage**, not cumulative ink load.

## Required behavior

For every analyzed page:

1. Treat the full page as **100% total area**.
2. Measure how much of that page area is actually covered by printed content.
3. Break that covered area into color categories so that:

   * each color shows a percentage of the full page
   * the total of all displayed color percentages **never exceeds 100%**
   * if all displayed color percentages are added together, they should equal the total covered area on the page
4. Any uncovered part of the page is blank paper and should not be counted as ink coverage.

## Important rule

The displayed color percentages must be based on **mutually exclusive page regions**.

That means:

* a single pixel or area of the page must belong to only **one displayed category**
* do **not** count the same pixel in Cyan, Magenta, Yellow, and Black at the same time
* do **not** use additive CMYK channel totals for the displayed percentages

## How to classify color coverage

For display purposes, assign each non-white pixel to one dominant bucket only.

Use a single classification result per pixel, such as:

* Black
* Cyan
* Magenta
* Yellow
* Red
* Green
* Blue
* Gray
* Other / Mixed Color

If using CMYK mode, still make the displayed page percentages mutually exclusive.
Do not show per-channel CMYK values in a way that lets the total exceed 100%.

If needed, keep technical CMYK ink-load data internally or in a separate advanced section, but the main user-facing coverage percentages must stay within 0–100% total page area.
